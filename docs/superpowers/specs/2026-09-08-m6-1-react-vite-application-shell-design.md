## 1. 设计结论

在现有 React/Vite 入口上建立中文、手机竖屏的可导航应用壳：使用 React Router 的声明式浏览器路由，统一最大 430px 的画布，分离普通页面、牌桌和全屏详情布局；提供页面渲染错误恢复及 Node 环境的 Vitest 入口。

本任务完成后，即使后端未启动，也能打开应用、切换主导航、进入组桌与设置、直接访问资源 URL、刷新并保留目标路由。资源页只显示页面标题、入口与明确的功能接入提示；它不宣称资源存在、查询成功或牌局可以操作。

本文拥有 M6.1 内部切片的路由、布局、恢复与验收契约。M5.5 是已完成的后端前置事实，不是本任务总设计；M6.1 也不代替 M6.2/M6.3 的状态同步协议。

## 4. 路由、导航与状态边界

### 4.1 路由表

以下为浏览器 URL，不是 Hono API。动态参数只是目标标识，不能成为资源存在性、Owner 或 Hand 状态的证明。

| URL                                 | 页面           | 布局 / 主导航 | 确定性上级入口           |
| ----------------------------------- | -------------- | ------------- | ------------------------ |
| `/`                                 | 训练首页       | 普通 / 训练   | 无；右上角设置           |
| `/sessions/new`                     | 选择阵容       | 普通 / 训练   | 训练首页                 |
| `/sessions/new/confirm`             | 确认开场       | 普通 / 训练   | 选择阵容                 |
| `/sessions/:sessionId`              | 牌桌           | 牌桌 / 隐藏   | 训练首页，文案“离开牌桌” |
| `/sessions/:sessionId/current-hand` | 本手流程       | 全屏 / 隐藏   | 对应牌桌                 |
| `/sessions/:sessionId/agents`       | AI 状态        | 全屏 / 隐藏   | 对应牌桌                 |
| `/history`                          | 历史           | 普通 / 历史   | 训练首页可经主导航到达   |
| `/hands/:handId`                    | 已完成手牌详情 | 全屏 / 隐藏   | 历史                     |
| `/statistics`                       | 统计           | 普通 / 统计   | 训练首页可经主导航到达   |
| `/settings`                         | 设置           | 普通 / 训练   | 训练首页                 |
| `/debug`                            | 调试入口说明   | 全屏 / 隐藏   | 设置                     |
| `/debug/hands/:handId`              | 手牌关联调用   | 全屏 / 隐藏   | 调试入口                 |
| `/debug/agent-runs/:runId`          | 调用详情       | 全屏 / 隐藏   | 调试入口                 |
| 未匹配 URL                          | 页面不存在     | 全屏 / 隐藏   | 训练首页                 |

组桌路径使用静态 `new` 段，不能被动态 sessionId 路由吞掉；路径生成与匹配使用同一份路由定义/常量，不维护两套独立字符串表。路由表保持有限、直接，不设计插件式注册或通用菜单生成语言。一级导航用链接和当前页标记；设置归属训练区，但不增加第四个 Tab。

本场历史使用 `/history?sessionId=...`，沿用同一个历史页；本任务只生成该链接并保留 URL，不执行筛选或复制 M5.3 查询解析。历史、统计的其他 URL 筛选由 M6.2/M7 按公开协议解析，Router 不清空已有 search。当前手是 Session 的实时工具页，完成手详情是 Hand 资源页，两者不能仅靠前端“已结束”标志互换。

### 4.2 返回、刷新与资源入口

页面内返回默认使用表中的明确上级链接，文案写清“返回牌桌”“返回历史”“返回调试入口”；不以 `history.length` 判断上一页是否属于本应用，不直接用无条件 `navigate(-1)` 实现兜底返回。浏览器自身的后退/前进保留正常语义。

从历史或调用列表进入详情时，允许携带一个仅用于返回的导航状态 `{ pathname, search }`，以恢复来源列表的筛选与页位置参数。返回目标必须匹配本站已登记的历史/手牌调用列表路由；不能接受协议、域名、任意 returnUrl 或业务实体。没有合法来源（含直接打开、新标签页）时使用确定性上级。M6.1 负责此小型导航策略；M7 负责从真实列表传入其 URL，不把 Session/Hand/Run 对象传入 location.state。

路由参数、search 和必要返回位置是导航状态。牌局、人物、统计、Provider 与调用记录以后只从 TanStack Query 读取；应用壳不保存这些实体，不使用 localStorage 恢复牌局，也不通过隐藏页面留存它们。

所有资源路径可直接打开和刷新。M6.1 骨架仅说明功能尚待接入，不基于 URL 伪造“该场正在进行”或“手牌已完成”。真实 ID 格式校验、404、删除后失效与 completed-only 可见性由 M6.2/M7 消费服务端响应落实。调试入口暂说明从手牌或 AI 状态进入，不展示虚构调用，也不增加手工输入资源 ID 的产品表单。人工路由验收可直接在地址栏使用测试 ID。

### 4.3 依赖与装配

```text
main.tsx（StrictMode + 根错误边界）
  → App（BrowserRouter + 共用手机画布）
    → 路由与页面错误边界
```

未来 QueryProvider 应在 Router 页面树之上保持稳定；本任务不提前创建空 Provider、请求层或 Store。离开牌桌是浏览器导航，不能结束场次、取消模型或修改服务端状态。旋转屏幕也不能重新创建 Router 或业务 Provider。

## 5. 手机画布与交互

### 5.1 布局责任

统一外层画布 `width: 100%`、`max-width: 430px`、水平居中，外围为近黑背景。支持范围内不设置导致横向溢出的 360px min-width。保持浏览器文字缩放与页面缩放能力。

使用 `100dvh` 高度和纵向 flex/grid：标题、可滚动内容、底部区各占独立行；内容行 `min-height: 0` 并承担纵向滚动。普通布局的底栏不随正文滚走，也不压盖正文最后一项。牌桌布局复用高度与安全区基础，但由自身提供顶部场次栏和底部操作区；M6.1 只保留容器和接入提示，座位、椭圆桌面、工具栏避让与下注交互由 M7 实现。

全屏指占满手机画布，不调用浏览器 Fullscreen API；独立全屏工具页不同时渲染牌桌、主导航或隐藏的旧业务页面。短屏优先压缩非必要留白，正文可滚动；不缩放整个应用或裁掉导航。页面级滚动容器每次 pathname 切换从顶部开始，search 更新不由壳强制重置；列表精确滚动位置恢复归 M7。

### 5.2 安全区、样式与可访问性

`index.html` 的 viewport 增加 `viewport-fit=cover`，保持 `lang=zh-CN`。手机画布统一承担顶部、左右安全区；每种布局的底部栏承担底部安全区，没有底栏的全屏布局由内容末端承担。页面不能再次叠加同一个 inset。

沿用已确认的克制深色牌室方向：近黑背景、深色表面、低饱和边界、青绿色交互强调；建立本任务实际使用的少量 CSS 变量，M6.5 原位完善。中文使用本机系统字体栈，不下载字体。这里只实现导航、标题、基本链接/按钮、占位和错误提示的必要样式，不提前实现 M6.5 组件库。

主要点击区域至少 44×44 CSS px。主导航有中文文字、`aria-current` 与非纯颜色的选中表达；图标若使用，只能辅助文字。每页一个主要标题与 main 区域。pathname 改变时更新文档标题，并把焦点移至新页面标题/主内容；search 筛选变化不抢走输入焦点。焦点边框清晰，键盘能到达导航与恢复操作；初版无需动画，后续动效遵守减少动态效果偏好。

### 5.3 横屏提示的可检验规则

上位需求同时要求“手机横屏旋转提示”和“桌面居中显示手机画布”。因此不对所有 landscape 视口统一遮挡。M6.1 将提示条件定义为：主指针为 coarse、视口宽度大于 430px、高度不超过 430px，且横向。对应媒体查询为 `(pointer: coarse) and (min-width: 431px) and (max-height: 430px) and (orientation: landscape)`。

该规则覆盖目标 360–430px 手机旋转后的视口；普通鼠标桌面窗口继续显示居中画布。目标手机竖屏打开键盘后宽度仍不超过 430px，不因高度缩短误显示旋转提示。这是目标视口策略，不宣称识别所有设备型号；平板仍使用居中画布，不扩展独立平板布局。

触发时显示“请旋转至竖屏”，内容区退出交互与可访问树；提示显示期间 Router/未来 Provider 保持挂载、URL 不变。可通过共享 matchMedia 状态给内容设置 hidden/inert 并管理提示焦点；恢复竖屏后回到当前页标题。监听必须清理，StrictMode 下不能重复订阅。首次载入横屏也应直接呈现提示，无可操作的底层导航。

## 6. 错误恢复与深链接宿主

根错误边界位于 Router 外，承接应用布局或 Router 子树的渲染失败，显示最小中文错误页，提供原生“返回训练首页”链接和用户触发的刷新。该页不依赖 Router、业务 Provider 或同一套可能失败的复杂布局。

页面错误边界保护路由页面内容，保留正常的标题/导航和手机画布；提供“重新显示”和上级入口。重新显示只重置当前错误状态，切换 pathname 也重置；不能自动循环重试，不清空全部缓存或本地设置。壳本身抛错时由根边界收敛。

错误页只显示固定中文说明，不渲染 Error.message、stack、完整 URL/query 或载荷；本任务不增加远程错误采集服务。React 开发模式自身的诊断不作为产品错误文案。事件回调、异步请求、HTTP 错误和脚本尚未加载的故障不在 React 渲染边界保证范围内；前两类由实际操作处理，API 状态由 M6.2/M6.6 接续。

BrowserRouter 使用正常路径。开发和构建后本地预览必须验证“直接请求深路径 → index.html → 同一路由页面”，不能只验证客户端点击。未来静态部署宿主须把浏览器页面 GET 路径回写到 index.html；静态文件仍按真实路径服务，`/api/*` 仍交给 Hono，不能把 API 错误变成 HTML。此宿主要求在部署阶段落实，本任务不修改后端监听、Host/Origin 或部署拓扑。

本轮不新增 API 代理；独立运行 `pnpm run dev:web` 即可验证应用壳，避免因启动整个后端而连接远程数据库。

## 7. Web 测试设施与验收

### 7.1 命令和类型检查契约

实施时在 `apps/web` 增加独立 Vitest 配置，固定 `environment: 'node'`，只收集 Web 的 `test/**/*.test.ts`，不继承服务端的数据库测试发现范围。测试直接从 Vitest 导入 API，不依赖全局类型；Web 类型检查包含 src、test、Vite 与 Vitest 配置。沿用现有 TS 严格选项。

命令接线如下：

| 入口                 | 行为                                                                                        |
| -------------------- | ------------------------------------------------------------------------------------------- |
| Web `test`           | `vitest run`，没有测试时失败，不加 passWithNoTests                                          |
| 根 `test:web`        | `pnpm --filter @tx-holdem-coach/web run test`                                               |
| 根 `test`            | 保留现有 test:backend，再顺序执行 test:web                                                  |
| 根 `verify`          | 保留地图、资源、Eval、格式、类型及后端测试，在既有后端测试后增加 test:web，避免重复执行后端 |
| Web 与根 `typecheck` | 覆盖新测试和配置；不以 Vitest 能转译代替 TypeScript 检查                                    |

### 7.2 最小可信自动化证据
