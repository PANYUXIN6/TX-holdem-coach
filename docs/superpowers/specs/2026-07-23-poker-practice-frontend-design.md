## 1. 设计目标

前端需要让用户在手机竖屏中长期、专注地进行扑克练习，同时清楚表达服务端状态、AI 等待、错误暂停和恢复过程。

设计原则：

1. 牌桌是对局页的绝对主角，历史、AI 状态和调试信息按需进入独立视图。
2. 服务端是唯一权威状态，前端不自行推演合法动作、下注金额或扑克结果。
3. 当前行动、连接状态和牌局暂停必须立即可见且可理解。
4. AI 故障必须显式暂停，不以静默代打掩盖问题。
5. Coach 复盘必须让用户区分当时决策依据与事后已知结果，不把结果论伪装成过程评价。
6. 首版只做中文手机竖屏体验，不维护独立桌面、平板、横屏或多语言布局。

### 1.1 技术与状态归属

- React + Vite + TypeScript 构建单页应用，不使用 TanStack Start。
- TanStack Query 管理所有服务端状态：预设人物目录、场次快照、历史、统计、供应商健康状态和 Agent 调用记录。
- Coach 复盘列表、状态和结构化报告也由 TanStack Query 管理，不复制到 Zustand。
- Zustand 管理页面级或跨组件的纯客户端状态，例如右侧工具栏选中项、牌桌页共享的下注草稿、基础动画队列、全局弹窗和提示。
- 只被一个组件或紧密组件子树使用的状态留在组件内，优先使用 `useState` 或 `useReducer`，不为简单局部状态创建全局 Store。
- 不建立覆盖全站的巨型 Zustand Store；按页面或明确领域拆分 Store，并使用选择器缩小订阅范围。
- 可分享或可刷新的历史与统计筛选条件进入 URL 查询参数，不重复放入 Zustand。
- Zod Schema 从 `packages/contracts` 共享，用于校验 HTTP 和 SSE 数据；校验失败时不写入 Query 缓存。
- 前端只识别 `packages/contracts` 支持的 `protocolVersion`，不接触服务端私有的 `snapshotSchemaVersion`、`eventSchemaVersion` 或 Drizzle 迁移版本。

严格边界：

- Zustand 不发起服务端请求，不保存服务端实体副本，不计算合法动作或其他扑克规则。
- TanStack Query 缓存是服务端数据在前端的唯一副本；组件从 Query 选择所需字段。
- SSE 连接状态、工具栏开关等客户端运行状态可以进入 Zustand，但 SSE 携带的权威快照必须写入 TanStack Query。

## 2. 设备范围与应用外壳

### 2.1 目标设备

- 可玩视口宽度为 360–430 CSS px，首版只支持手机竖屏。
- 使用 `env(safe-area-inset-top)` 和 `env(safe-area-inset-bottom)` 保护顶部状态栏、刘海、圆角和底部手势区域。
- 页面宽度超过 430px 时，应用在视口中央显示最大 430px 宽的手机画布，外围保持近黑背景，不扩展成桌面布局。
- 横屏只显示“请旋转至竖屏”的轻量提示，不维护第二套牌桌布局。
- 牌桌优先适配常见手机高度；短屏通过缩小牌桌内部间距和座位尺寸处理，底部操作区不得被压出可视区域。

### 2.2 全局导航

普通页面使用：

- 顶部标题栏。
- 单列纵向内容。
- 底部“训练、历史、统计”主导航。

设置通过训练首页右上角进入，不占用主导航位置。

进入牌桌后隐藏底部主导航，改用：

- 顶部场次栏。
- 右侧悬浮工具栏。
- 底部固定玩家操作区。

离开牌桌进入本手流程、AI 状态、历史或调试视图时，不把扑克状态复制到路由状态。返回牌桌后从 TanStack Query 获取当前缓存，并通过服务端最新快照校准。

## 3. 信息架构

### 3.1 训练首页

展示：

- “新建训练场”主操作。
- 未完成场次的“继续训练”卡片，包含当前手数、用户筹码和 AI 阵容。
- “沿用上一场阵容”快捷入口；它只复制人物配置，不复制任何场次记忆。
- 最近场次的日期、手数和净盈亏摘要。
- DeepSeek 与 Kimi 的连接摘要。
- 设置入口。

如果存在未完成场次，“继续训练”的优先级高于“新建训练场”。用户不能同时运行两场。

首版不提供 AI 人物管理入口。

### 3.2 新建训练场

使用适合手机的两步确认流程：

1. **选择阵容**
   - 从后端只读预设人物目录选择 5–8 个不同人物。
   - 人物卡只显示彩色文字头像、姓名、背景/教学摘要和风格摘要，不显示模型标识、模型参数或“模型配置摘要”。
   - 可以沿用上一场阵容。
   - 本地用户领域座位固定为 `0`，不显示用户座位选择器，也不向创建接口提交 `userSeatNumber`。
   - 可以调整或随机排列 AI 的 `1..8` 座位；随机排座只改变 AI 座位映射，不决定首手按钮。
2. **确认开场**
   - 显示固定小盲 10、大盲 20和每席初始筹码 2,000。
   - 显示最终阵容及顺序。
   - 检查 DeepSeek 必需配置和 Kimi 降级配置。
   - 创建本场人物配置快照；首手按钮由服务端安全随机并随创建响应返回，前端不预选或覆盖。
   - 使用服务端确认的初始快照开始第一手。

开场后阵容锁定。前端不提供人物创建、编辑、复制、删除或导入操作。

### 3.3 牌桌页

牌桌页包含：

- 顶部场次栏：返回、盲注、手数、当前街道、当前行动和连接状态。
- 纵向大椭圆牌桌。
- 最多九个座位。
- 右侧悬浮工具栏。
- 底部固定玩家操作区或手牌结算区。

右侧悬浮工具栏提供：

- **本手**：打开当前手完整动作流程。
- **AI**：打开本场各 Agent 的状态与人物摘要。
- **历史**：打开本场已经完成的手牌列表。

工具栏固定在顶部栏下方的右侧安全区域，必须避开四个右侧座位的主要点击区域。短屏无法同时容纳三个按钮时折叠为一个“工具”按钮，展开后仍提供本手、AI 和历史三个入口。入口使用文字或图标加可访问名称，不能只依赖难以理解的抽象图标。

### 3.4 当前手与历史手牌详情

当前手和正常完成手牌共用独立全屏详情布局，不在牌桌右侧常驻动作时间线；`aborted` 手牌不进入普通历史详情。

详情按以下街道分组：

- 翻前。
- 翻牌。
- 转牌。
- 河牌。
- 摊牌。

每个动作显示：

- 行动顺序。
- 行动者和逻辑位置。
- 动作及“本街投入到多少”的金额。
- 行动后的筹码和底池。
- 未跟注投入返还。

当前手详情：

- 只展示服务端当前允许公开的信息。
- 不提供审计揭牌。
- 返回后恢复牌桌，并读取最新快照。

正常完成手牌详情额外展示：

- 用户底牌和公共牌。
- 最终牌型。
- 各底池赢家和分配。
- “揭示全部底牌”审计操作。
- 关联 Agent 调用入口。
- “请求教练复盘”入口和已有复盘状态。

默认显示用户底牌和进入摊牌的未弃牌玩家底牌；弃牌玩家及因他人全部弃牌而直接获胜者的底牌默认隐藏。只有 `completed` 手牌可以请求服务端的审计揭示视图。前端不能先接收完整底牌再自行隐藏。

不提供备注、打法标签、动画重放或逐步回放控制。

### 3.5 历史页

历史页按场次分组显示纵向手牌卡片。手牌卡至少包含：

- 时间和手牌序号。
- 用户逻辑位置。
- 用户起手牌和公共牌。
- 单手净盈亏。
- 最终结果摘要。

顶部筛选按钮打开底部筛选抽屉，支持：

- 日期范围。
- 场次。
- 用户逻辑位置。
- 用户单手结果：盈利、亏损或持平。
- 用户标准起手牌类别，例如 `AA`、`AKs`、`AKo`，不区分具体花色。
- 参与场次的 AI 人物配置快照。
- 分页与排序。

筛选状态写入 URL 查询参数。人物预设以后发生修改时，历史仍按创建场次时固化的名称、人物标识和版本显示及筛选。

### 3.6 统计页

顶部使用与历史页一致的底部筛选抽屉，支持日期、场次、逻辑位置、用户或 AI 以及 AI 人物配置快照。

首版指标：

- 手牌数。
- 净盈亏。
- VPIP。
- PFR。
- 3-bet。
- 摊牌率。
- 摊牌胜率。

指标使用纵向或两列卡片展示，不依赖宽屏表格。每个百分比同时显示分子、分母、百分比和中文解释；样本较小时仍显示原始计数，分母为 0 时显示“—”。趋势只使用简单折线图或柱状图，不展示求解器、EV 或最优行动结论。

### 3.7 设置页

提供：

- DeepSeek 和 Kimi 的非敏感配置摘要。
- 最近一次连接检测状态：未配置、未检测、可用或不可用。
- 显式“检测连接”操作；普通页面加载和 Provider 查询不得自动触发供应商网络请求，检测中的加载态由前端 mutation 本地维护。
- API Key 是否已配置的布尔状态，不显示密钥内容。
- DeepSeek 是否可创建场次、Kimi 是否可用于降级；这两个能力只由 Key 是否配置决定，最近检测失败仅作诊断提示。
- 可空的最近检测时间与脱敏错误码；不显示模型标识、路由、原始供应商错误或响应正文。
- Player 单次供应商尝试超时，默认 15 秒，合法范围 5–30 秒。
- Player 完整决策总 deadline，默认 45 秒，合法范围 15–120 秒且不得小于单次尝试超时；修改只影响之后新建的 Player 运行。
- 数据目录只读展示。
- 删除已结束场次与清空全部数据。

预设人物目录不是用户数据，清空全部数据后仍保留。

### 3.8 AI 状态与调试视图

AI 状态页展示本场人物的：

- 彩色文字头像、姓名、座位和预设版本。
- 当前筹码和公开状态。
- `idle`、`thinking` 或 `paused` 运行状态。
- 当前供应商、降级和纠错摘要。
- 进入详细调用记录的入口。

调试视图展示：

- 请求标识、扑克状态版本和场次事件序号。
- 角色、服务商和模型。
- DeepSeek→Kimi 路由原因。
- 脱敏请求。
- 最终原始输出；不显示供应商隐藏推理或 `reasoning_content`。
- 归一化决策。
- Schema 与扑克规则校验错误。
- 两次自动纠错过程。
- 延迟和 Token 用量。

牌局暂停时，顶部显示明确错误摘要、“重新请求当前 AI 行动”和“中止本手并结束场次”入口。不提供本地策略或替 AI 选择行动。

### 3.9 Coach 复盘视图

只有 `completed` 手牌显示“请求教练复盘”。点击后创建独立复盘请求，不阻塞返回牌桌或开始下一手。界面展示：

- `pending`、`running`、`completed`、`failed` 四种状态。
- 牌局概况、策略数据集版本和适用假设。
- 按街道及权威行动顺序排列的每个用户决策。
- 每个决策的策略基准、局面约束、对手证据和事后解释。
- 每个决策由确定性分类器冻结的 assessment、决策标签、严重度、基准对比和 EV 可用状态。
- 最多 3 条核心课程和最多 3 条练习建议。
- 可选的 13×13 翻前范围矩阵，并高亮用户实际手牌。

展示规则：

- `exact`、`referenceOnly`、`unsupported` 必须显示文字，不只使用颜色或图标。
- “动作执行频率 75%”和“下注尺度 75% 底池”使用不同标签；禁止显示没有限定词的“下注 75%”。
- 事后解释使用独立区块和明确标题，不能在视觉上与当时过程评价混为同一结论。
- 对手样本不足时展示分子、分母及“证据不足，不进行剥削偏离”。
- EV 不可用时显示“EV 暂无可靠数据”，不显示模型估算数值。
- 决策标签只附着在当前决策，不聚合或渲染为长期用户画像。
- 失败时展示脱敏错误摘要和“重新生成”操作；重新生成创建新报告，旧报告保持可查看。
- 报告使用纵向卡片和渐进展开，不在 360–430px 内压成多列表格或高密度仪表盘。

`RangeMatrix` 只消费严格校验后的 `rangeChartSpec`。前端不执行模型返回的 Python、HTML 或脚本，也不自行推导策略频率、逻辑位置、SPR、底池赔率或下注尺度。

## 4. 牌桌布局

采用已确认的手机竖屏沉浸牌桌：

- 大椭圆牌桌占据顶部栏与操作区之间的绝大部分空间。
- 领域座位 `0` 是唯一用户座位，固定投影到底部中央，底牌位于用户座位上方；视觉位置不产生另一套座位号。
- AI 领域座位 `1..8` 按顺时针次序映射到八个稳定锚点：顶部左右各一席，左右两侧各三席；人数不足九人时按对称、优先保留上下间距的规则隐藏未入座锚点，不压缩或重编号实际领域座位。
- 底池、公共牌和当前街道位于桌面中心。
- 庄家按钮、下注筹码和动作标记靠近对应座位。

座位只显示：

- 彩色文字头像。
- 姓名。
- 逻辑位置。
- 当前筹码。
- 本街已投入筹码或最近动作。
- 当前行动、高亮、思考中、全下或已弃牌状态。

座位不显示风格标签、VPIP、PFR 或其他 HUD。详细人物画像只在 AI 状态页展示。

AI 底牌严格使用服务端可见性投影。前端不接收未公开牌后再通过 CSS 隐藏。

## 5. 玩家操作

### 5.1 合法行动

底部操作区根据服务端下发的合法动作集合渲染：

- 弃牌。
- 过牌。
- 跟注及跟注额。
- 下注。
- 加注。
- 全下。

不显示当前状态下不可能的操作。主动作按钮使用大触控区域，并位于底部安全区域上方。

### 5.2 金额选择

下注或加注支持：

- 最小加注。
- 1/2 底池。
- 2/3 底池。
- 满池。
- 全下。
- 精确数字输入。

快捷金额使用可横向滚动的单行按钮。精确输入调用数字键盘，不提供滑杆。

金额语义统一为“本街投入到多少”，避免“再加多少”和“加到多少”混淆。最小加注、1/2 池、2/3 池和满池均使用服务端 `suggestedTargets`，前端不计算底池比例公式。前端根据服务端给出的最小值、最大值和当前投入即时验证；后端再次验证。

提交后立即禁用操作区并显示处理中状态，直到收到已提交事件或错误响应。前端不预先移动筹码。

## 6. 一手结束与场次控制

一手结束后，底部操作区切换为结算摘要：

- 获胜座位。
- 获胜牌型。
- 各底池分配。
- 未跟注投入返还。
- 每个座位的筹码变化。

此时用户可以：

- 打开本手详情并手动请求 Coach 复盘。
- 补码至最多 2,000。
- 开始下一手。
- 结束场次。

只有“开始下一手”成功时，归零 AI 才在同一事务中自动买入 2,000，并在界面动作流程中显示对应事件。直接结束场次不买入；用户余额为 0 且尚未补码时，先阻止开始下一手，不触发 AI 买入。

一手进行中不提供结束场次、补码、撤销或重开。

## 7. 状态同步

### 7.1 命令

前端通过 TanStack Query Mutation 经 HTTP 提交命令，不做扑克状态的乐观更新。命令包含：

- 命令唯一标识。
- 场次标识。
- 当前预期状态版本。
- 命令类型和负载。

### 7.2 事件

前端通过场次 SSE 接收下列已持久化的扑克事件和 Player 协调事件。`stateVersion` 只比较权威扑克状态；场次内单调递增的 `eventSeq` 只用于排序、去重该 SSE 流中的扑克及 Player 协调事件，每个事件另带全局唯一 `eventId`。Coach 使用独立复盘生命周期，不进入该事件流：

- 权威状态快照。
- 已提交行动。
- AI 思考开始。
- DeepSeek→Kimi 降级。
- Harness 自动纠错。
- 牌局暂停。
- 手牌正常完成、手牌中止和场次结束。

只有 `stateVersion` 高于本地版本的 `PublicSessionSnapshot` 才能替换 `['session', sessionId]` 中的扑克状态。同一 `stateVersion` 下更高 `eventSeq` 的会话协调事件仍必须处理，包括 Agent 运行状态和场次结束；它们更新场次 Query 中的协调字段，或使关联调用链 Query 失效。Zustand 不保存这些服务端事件。

### 7.3 重连

SSE 断开时：

1. 在顶部场次栏显示“正在重新连接”。
2. 禁止新的玩家行动。
3. 使用最后处理的 SSE `eventSeq` 作为 `Last-Event-ID` 自动重新订阅。
4. 顺序补收遗漏的已持久化事件。
5. 重连成功后读取由服务端组合生成、包含当前生命周期、`agentRunState` 和有效请求摘要的最新 `PublicSessionSnapshot`。
6. 通过 TanStack Query 使当前场次查询失效并重新获取。
7. 丢弃旧版本缓存，以服务端版本为准；Zustand 不参与快照恢复。

历史、统计和设置的写操作成功后，只使对应 Query Key 失效。场次结束或离开牌桌时重置该页面的 Zustand UI 状态，不影响 Query 缓存和服务端数据。

Coach 创建和重新生成通过独立 Mutation 完成。它们只使目标手牌的 Coach Query 失效，不修改场次快照 Query、扑克 `stateVersion` 或 SSE 游标。

快照或状态版本异常时进入只读诊断页，展示错误标识和恢复建议，禁止继续发送扑克命令。

## 8. AI 等待与暂停

AI 思考期间：

- 高亮当前 AI 座位并显示“思考中”。
- 右侧 AI 工具入口显示进行中标记。
- 保持本手流程、AI 状态、历史和调试视图可打开。
- 不显示倒计时承诺，因为外部服务延迟不可保证。

DeepSeek 降级到 Kimi 时，只在 AI 技术状态和调用记录中显示，不伪装成扑克行动。

最终暂停时：

- 冻结扑克操作。
- 保持牌桌和已持久化日志可查看。
- 明确显示失败阶段、服务商和请求标识。
- 提供“查看调试信息”“重新请求当前 AI 行动”和“中止本手并结束场次”。
- 中止入口只在 `active + inHand + paused` 时出现，并使用高风险二次确认，明确提示当前手不会进入普通历史、统计或 Coach，筹码和场次摘要将恢复到开手前。
- 不提供“使用本地策略”或“替 AI 选择行动”。

服务重启后，原来处于思考中的旧运行显示为已取消，并由带新请求标识的新 Player 运行从 DeepSeek 重新开始；前端不得继续展示旧运行正在执行。原来已经暂停的请求继续显示暂停，必须人工重试。浏览器刷新不取消服务端有效请求。

## 9. 视觉方向

采用参考图启发的克制深色手机牌室：

- 近黑页面背景。
- 深青绿色椭圆牌桌和低饱和边框。
- 青绿色用于当前状态与可交互信息。
- 蓝、绿、红分别区分弃牌、过牌/跟注和下注/加注主按钮，同时保留明确文字。
- 扑克牌保持白底高对比。
- 头像使用姓名首字或前两个字符以及预设高对比度背景色，不使用人物图片、上传头像或外部头像服务。
- 错误、暂停和危险删除使用红色与明确文字，不只依赖颜色。

避免：

- 霓虹赌场风。
- 过度金色装饰。
- 拟真 3D 桌面。
- 高密度数据仪表盘。
- AI 生成式渐变和无意义玻璃拟态。

## 10. 动画、触控与可访问性

只使用基本二维动画：

- 发牌出现。
- 筹码移动。
- 当前行动位切换。
- 底池分配。
- 页面和工具视图短促过渡。

不使用音效。动画不得阻塞操作；系统启用“减少动态效果”时，去除移动与缩放，仅保留必要淡入或立即切换。

其他要求：

- 主要触控目标原则上不小于 44×44 CSS px。
- 精确下注输入使用适合金额的数字键盘。
- 整个页面不产生横向滚动；只有快捷金额行允许自身横向滚动。
- 所有交互可通过键盘到达，焦点状态清晰。
- 颜色不是唯一状态提示。
- 扑克牌、筹码额和行动按钮保持足够对比度。

## 11. 前端验收

必须验证：

1. 360–430px 手机竖屏布局、顶部与底部安全区域以及短屏压缩可用。
2. 宽屏只居中承载最大 430px 手机画布，横屏显示旋转提示。
3. 可以读取至少八个后端预设人物、选择 5–8 个不同人物、调整顺序、沿用符合当前人数限制的上一场阵容并创建场次。
4. 前端不存在人物创建、编辑、复制、删除或导入入口。
5. 牌桌为纵向大椭圆九席布局，6、7、8、9 人四种人数下，右侧工具栏和底部操作区都不会遮挡关键座位、公共牌或用户底牌。
6. 当前手和历史手牌使用独立全屏分街流程，不实现动画重放。
7. 牌桌和详情只显示服务端允许的信息。
8. 快捷金额和精确输入无法提交超出服务端边界的值，界面不存在滑杆。
9. 提交行动后不会出现重复操作或前端预先移动筹码。
10. SSE 断线和刷新后可以按 `eventSeq` 补发，并恢复最新扑克状态与 Agent 运行状态。
11. DeepSeek→Kimi 降级、自动纠错和最终暂停均有明确反馈。
12. 一手结束后可以补码、继续或结束；AI 自动买入只随成功的下一手命令发生。
13. 历史按街道展示行动并执行服务端可见性投影。
14. 固定统计口径、整场删除和清空全部数据流程可用。
15. TanStack Query 是服务端数据的唯一前端缓存，Zustand 中不存在服务端实体副本或请求函数。
16. HTTP 与 SSE 响应必须通过共享 Zod Schema 后才能进入界面状态。
17. 页面不存在备注、用户可编辑标签、长期打法画像、数据导入或导出入口；Coach 的只读逐决策分类标签不受此限制。
18. 只有正常完成的手牌可以手动请求 Coach；`aborted` 手牌不出现在普通历史或 Coach 入口中。Coach 请求运行、失败、重新生成和查看旧报告都不阻塞牌局或改变场次快照。
19. 每个用户决策按顺序展示策略基准、局面约束、对手证据和独立事后解释，且 `referenceOnly`、`unsupported` 与样本不足均有明确文字。
20. 动作执行频率与下注尺度使用不同标签，不出现含义不明的“下注 75%”。
21. 13×13 范围矩阵在 360–430px 下可阅读，并且只由严格 Schema 的 `rangeChartSpec` 渲染。
22. 每个 Coach 决策展示冻结标签、严重度和 EV 状态；LLM 无权修改的字段在前端也不允许编辑。
23. Player stale 接替或服务重启创建新运行期间保持 thinking，最终失败显示 paused；界面不提供超时自动弃牌。
24. 只有暂停中的进行中手牌显示“中止本手并结束场次”；确认后界面以更高版本的回退快照结束场次，不把中止手加入历史、统计或 Coach。
25. 人物页面不显示模型配置；Provider 可用性和连接状态只来自独立设置/健康查询。
26. 设置页分别解释单次尝试超时和完整 Player 决策 deadline，Coach 长任务不会阻塞 Player 行动。
27. 用户领域座位始终为 `0` 并显示在底部；组桌只排列 AI 的 `1..8` 座位，前端不能提交用户座位或首手按钮。
28. Provider 查询不自动联网；手动检测只展示共享协议允许的四种状态、时间和脱敏错误码，检测失败不会错误地关闭已配置的开场或降级能力。
