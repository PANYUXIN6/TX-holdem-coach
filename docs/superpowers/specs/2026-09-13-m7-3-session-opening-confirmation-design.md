## 1. 结论与范围

将 `/sessions/new/confirm` 从 M7.2 的只读交接摘要补齐为可以实际开场的确认页：展示最终座位、人物版本、固定规则和 DeepSeek 配置/检测结果，允许调整或随机排列 AI，点击“确认开场”后通过原创建 runtime 进入服务端返回的场次。

推荐方案是“原生座位选择器 + 提交前只读复核 + 原创建 Mutation”。M7.2 已完成需要的公开协议、历史绑定和服务端排座，本任务主要落在 Web 的 `session-setup`。不需要新 API、数据库结构或另一套创建服务。服务端继续负责 Owner 互斥、活动冲突、历史来源锁内认证，以及场次、首手检查点、下盲和发牌的一次原子提交。

必须满足的结果：

1. 用户座位固定为 0，5–8 位 AI 在 1..8 中各占唯一座位；确认页可以理解并改变最终顺序。
2. 普通模式使用已选择的当前人物，沿用模式完整保留已接受的历史配置与版本；两者均创建新 Agent 实例和空记忆。
3. 清楚展示小盲 10、大盲 20、每席初始筹码 2,000（100BB），以及开场后阵容锁定。
4. DeepSeek 配置可用是开场条件；手动检测是诊断操作，`notChecked` 或 `unavailable` 不额外禁止开场。
5. 创建成功直接接收第一手 `inHand` 快照并导航；活动冲突或不确定结果有明确恢复路径，不自动再次创建或补发首手命令。

研发按本文 A → B → C → D 切片推进。组件拆分与局部组织由实施者决定；不得在切片内改写来源、配置门槛、首手原子性及失败恢复语义。

## 4. 页面与排座交互

### 4.1 信息顺序

1. 步骤“组桌准备 / 02 确认开场”，标题“确认你的训练场”；显示“共 N 人 · 你和 N−1 位 AI”。
2. 规则摘要：小盲 10、大盲 20、每席初始筹码 2,000（100BB）；“首手庄位由系统随机决定，开场后阵容锁定”。这里是入桌筹码，牌桌响应中下过盲注的余额不必仍为 2,000。
3. 阵容来源：普通模式“来自当前人物目录”；沿用模式展示已接受来源的结束时间，并说明“保留原人物版本，不继承上一场记忆”。失配时使用来源变化反馈，不能把新来源内容当作已接受阵容。
4. 排座区：用户“你 · 座位 0 · 固定”，AI 行显示文字头像、姓名、人物版本与目标座位选择器；区尾“随机排座”。
5. DeepSeek 配置及连接区，见 §6。
6. 操作区：当前阻塞原因、“确认开场”、保留来源的“返回选择阵容”。按钮附近说明创建后直接发出第一手。

确认页无需重复五项人物风格和长背景；返回选择页可以查看。人物版本以“版本 N”可见展示，不展示配置键、来源 UUID、模型标识或参数。完整来源标识只用于提交与认证。

### 4.2 初始与手动排座

普通选择时按选入顺序分配最小空闲 AI 座位，首次为 1..N。返回选择页不增减成员时保留排座；移除一人只释放该席，其余人的目标座位保持；新增人物占最小空闲席并追加到选择摘要。选择摘要顺序继续遵循 M7.2 的选入顺序，确认页按目标座位升序呈现实际入座顺序。

历史首次接受时沿用每人的 `sourceSeatNumber` 为目标座位，保留可能存在的空位。沿用模式的目标占席集合始终等于已接受历史来源的占席集合，只能在该集合内交换人物或随机排列，不能移入来源集合之外的空席。来源或配置键不变的后台读取不能覆盖已调座位；用户接受新的历史来源时，重新从新来源初始化，不能套用旧映射。

普通模式中，每位 AI 的原生选择器提供座位 1..8，选项注明“空位”或当前姓名；沿用模式仅提供已接受历史来源占用的座位，选项注明当前姓名，并显示帮助文字“沿用阵容仅可交换原有座位”：

- 选自己的当前席，无变化。
- 普通模式选空席，该人物移入目标席，原席变空；沿用模式不提供空席移动操作。
- 选已占席，两位 AI 在一次 reducer 更新中交换目标席。帮助文字说明“选择已有人的座位会交换两人”。

用户没有座位选择器。座位号表示固定领域编号及顺时针顺序，不在开场前标注 BTN/SB/BB/UTG，也不预演随机按钮。M7.4 拥有按实际入座顺序映射屏幕位置的视觉规则，确认页不提前建立另一份大椭圆布局。

列表用人物稳定身份作为 React key；历史身份为来源场次加来源座位，不使用目标座位。交换后保留发起操作的控件焦点，使用一句 `aria-live="polite"` 提示结果，例如“张三与李四已交换座位”。

### 4.3 随机排座

将所有已选 AI 在当前已占用的目标座位集合中均匀洗牌；空位集合保持不变。按钮旁说明“随机交换当前 AI 座位”。使用 Fisher–Yates，对交换下标均匀采样；这是可复核的 UI 随机排序，使用浏览器常规随机数即可，不能借此实现服务端首手按钮随机。

一次点击完成一次置换，允许恰好得到原排列，不循环抽样强迫变化。随机函数可在测试中注入固定随机输入以验证成员、目标席集合和来源绑定不变；不做随机分布统计测试。结果立即可见，用户仍可手动调整。

### 4.4 移动端与反馈

复用最大 430px 画布、`Avatar`、`Field`、`Button`、`StatusBadge`、`RequestError` 和现有 CSS 变量。窄屏姓名允许换行，控件单列且可读，触控目标至少 44px；规则摘要可以短行排列，不能引入页面横向滚动。

沿用 M7.2 已验收的内容末端普通流操作区，确保长名单和检测错误可滚动读完，且不覆盖 Shell 主导航。确认页自身就是最终审阅步骤，无须新增危险确认弹窗。来源修复、配置帮助和错误说明直接出现在相关区域，不跳转尚未实现的设置页才告诉用户如何处理。

## 5. 草稿与有效性

### 5.1 最小状态扩展

普通 `Selection` 增加 `seatNumber`，成为 `{personaId, personaVersion, seatNumber}`。历史沿用现有 `{sourceSessionId, assignments:[{sourceSeatNumber, configSnapshotKey, seatNumber}]}`。交换和随机只修改目标席；不得将 `sourceSeatNumber` 改为新席或由当前目录重新生成历史配置键。

草稿继续只保存用户选择与已接受引用。姓名、头像、人物实体、Provider 摘要、Query 成功状态及 Mutation pending 不复制进 reducer；排座有效性从当前草稿派生。提交期间用于核对的草稿引用和操作标识是短期控制状态，不做持久化。

共享纯规则负责：AI 人数 5–8、身份唯一、目标席在 1..8 且唯一、普通 ID/版本匹配当前目录、历史绑定完整匹配当前预览。`catalogMatches` 和 `previewMatches` 仍分别认证来源；目标席有效性额外检查，不通过重排数组隐式改变来源认证。

沿用模式还须明确校验：`assignments` 的目标 `seatNumber` 集合等于当前匹配预览中全体 AI 的 `sourceSeatNumber` 集合，同时保留全员来源席与配置键的匹配校验。该集合相等条件属于排座有效性，reducer 的交换/随机更新须保持它，确认资格及提交前复核均须检查；不等时不得生成创建请求。普通模式不受历史占席集合约束。以历史来源 `{1,2,3,4,5}` 为例，交换 1、5 合法，移动 1→8 不可操作，目标集合 `{2,3,4,5,8}` 也必须判为无效；无需等到服务端拒绝才发现不相容的排座。

### 5.2 页面生命周期

继承 M7.2 的两步 Provider、来源 search、清理和确认直达行为。已有草稿临时失配时保留引用供用户理解和修复；没有内存草稿才 replace 回同来源选择页。后台历史变化可以显示提示，但接受新来源统一回到选择页完成，避免确认页面自动接受后继续提交。

确认页读取 Provider 时要求本次挂载成功读取，不能拿首页的热缓存直接开放开场。使用已有 `useSetupQuery/readReady` 语义或在本模块内等价复用，不回退成只检查 `data`。读取中和读取失败均保留上次摘要供阅读，并关闭本轮创建资格。

提交相关状态分属：

| 状态 | 所有者 |
| --- | --- |
| 排座、来源引用 | 原流程 reducer/context |
| 复核中、复核错误、本次确认页操作标识 | 确认提交适配的 React 局部控制状态 |
| 创建请求 pending/error/result | 原 `createOptions()` 的 Mutation |
| 跨页创建在途、继续目标 | runtime 的现有 operations 订阅 |
| 检测请求状态 | 原 `checkProvider()` Mutation |
| Provider、阵容、active 和快照 | 原 Query/runtime 接收器 |

本页在复核或创建期间禁用排座、随机、来源切换及重复提交。全局导航、浏览器返回或页面卸载仍可能发生，因此所有异步完成分支都需要生命周期核对，不能只依赖按钮禁用。

## 6. DeepSeek 配置与手动检测

读取使用 `queries.providers()`，检测使用 `runtime.mutations.checkProvider()`，输入固定为 `{provider:'deepseek', body:{}}`。不得进入页面、点击开场、回到前台或自动重试时发起检测 POST。

| 安全摘要 | 展示与开场资格 |
| --- | --- |
| `configured=false / notConfigured` | “尚未配置 DeepSeek，暂不能开场”；提供就地说明：在后端私有环境配置 DeepSeek API Key，重启服务后点击“重新读取配置”。不提供浏览器 Key 输入框。 |
| `configured=true / notChecked` | “已配置 · 尚未检测”，显示“检测连接（可选）”；允许在其他条件满足时开场。 |
| `configured=true / available` | “已配置 · 上次检测可用”，展示检测时间及“仅代表上次检测结果”；允许开场。 |
| `configured=true / unavailable` | “已配置 · 上次检测不可用”，使用现有脱敏错误码中文映射；说明“仍可开场，实际 AI 调用失败时牌桌会暂停”；允许开场。 |
| 摘要读取中/失败 | 保留旧摘要但标记更新中/读取失败；重新读取成功前不使用旧 `canCreateSession` 开场。 |

开场配置资格直接消费经 Schema 校验的 `deepSeek.canCreateSession`；不从人物、检测颜色或错误码另算一份规则。缺 Key 时检测按钮不可用；已配置时检测在途禁用重复检测。检测期间仍可调整排座，暂时串行等待本次检测及其摘要刷新结束后再开场，不要求检测结果为 available。

保留原检测 options 的 `onSuccess` 和 Query 刷新。检测 HTTP 成功但刷新 GET 失败时，界面表达“检测请求已完成，状态读取失败”，可展示该次 Mutation 返回的安全结果并明确其来源；开场仍等待摘要重新读取成功。检测 HTTP 自身失败使用 `RequestError`，不得把传输错误伪造为供应商 `unavailable`。

## 7. 提交、并发与恢复

### 7.1 点击后复核

一次点击“确认开场”只代表对当前可见阵容、版本及排座的确认：

1. 同步检查当前来源和排座有效、Provider 可创建、无正在创建或检测；立即设置本页复核互斥，捕获不可变草稿引用、当前来源及本次页面操作标识，防止同一事件循环连点。
2. 显式重新读取原 active、Provider 和当前来源 Query。可以并发 GET，但须等待并逐项检查结果；使用原 queryFn/AbortSignal 和 active 接收器，不直接 fetch 或写入快照缓存。本轮复核应取得点击之后发起的读取；如已有在途 GET，先经 Query 取消后重取，不能让 `fetchQuery` 的缓存命中或旧请求合并冒充复核。
3. 只对所需来源读取：普通取当前目录，沿用取精确历史预览；不要求无关来源成功。任一读取失败、取消或再次进入读取中，终止本次提交。不能因 Query refetch 默认不抛错而只判断 Promise 已完成。
4. 核对页面操作仍有效、草稿仍是原引用、Query 尚未被删除/reset/失效，且当前资源与捕获来源相符。活动定位非 null 则停止创建，显示继续入口；普通 ID/版本失配或历史绑定变化则显示变化反馈，返回选择页修复，不能自动调整后接着 POST。
5. Provider 从可创建变成不可创建时停止并展示配置问题。检测时间或诊断状态变化只更新提示，不属于重新选择阵容的理由；它们也不改变 `canCreateSession` 的定义。
6. 同步构造并通过现有 `CreateSessionRequestSchema` 校验请求，随即委托 `runtime.createOptions()` 的原 mutationFn。适配层若包裹 options，必须完整保留其配置与生命周期；页面不得另写 API POST 或接收器。

旧读取或后台刷新与本轮复核交错时，以当前 Query 生命周期和当前草稿再认证；不要单凭捕获的三个 Promise 结果提交。前端复核减少过期确认，最终并发安全仍由服务器的活动互斥与历史绑定保证。

### 7.2 请求映射

| 草稿 | 实际创建体 |
| --- | --- |
| 普通 | `{rosterSource:{type:'currentCatalog', selections:[{personaId, seatNumber}]}}`，按目标席升序输出；`personaVersion` 仅用于客户端已见版本核对。 |
| 沿用 | `{rosterSource:{type:'latestEnded', preview:{sourceSessionId, assignments:[{sourceSeatNumber, configSnapshotKey, seatNumber}]}}}`，全员绑定，按目标席升序输出。 |

不发送用户座位、盲注、初始筹码、按钮、私有配置或旧记忆。历史不得省略 preview 退回无绑定模式。普通模式继承 M7.2 的不可变当前 published v1 契约；本任务没有新增版本绑定字段，不能宣称获得了协议并未提供的跨版本原子比较能力。未来更改目录版本/可变配置时，按 M7.2 §5.3 先修订提交绑定。

### 7.3 成功与活动冲突

成功由 runtime 认证并接收快照、更新 active 和相关缓存，页面只消费返回的 `sessionId`，replace 导航到 `resourcePath('table', id)`。清理草稿并结束本次操作，浏览器返回不会重放创建。创建响应是首手 `inHand`，接收器若已有更新版本，仍以接收器结果为准，不把它降回首手。

牌桌路由挂载原同步租用，继续执行 snapshot 信封与 GET 校准；到达地址不意味着立刻可以提交扑克行动。M7.3 验收到这一交接为止，牌桌布局与真实操作由 M7.4/M7.5 完成。

`ACTIVE_SESSION_EXISTS` 仍是失败 Mutation。若原 runtime 提供已认证的 `getCreateTarget()`，本次确认页仍有效时直接 replace 进入该活动场次，符合任务的网络重试验收；不把错误改成成功，也不发另一条创建或开手命令。复核阶段发现已有活动场次则显示“继续当前训练场”供点击，因为本次还未发创建请求。

### 7.4 不确定结果与业务失败

| 结果 | 恢复行为 |
| --- | --- |
| 网络错误、协议错误或服务错误，runtime 已定位活动 ID | 保留“开场结果未确认，已找到活动训练场”，展示“继续当前训练场”；不会再次创建。只有活动冲突按上一节自动导航，其余由用户明确继续。 |
| runtime 未给目标，active 读取仍失败/未完成 | 显示“暂无法确认是否已创建”，只给“重新读取活动场次”和返回入口；禁止直接重发 POST。 |
| 失败后的活动读取成功为 null | 显示“当前未发现活动训练场”；用户可以点击“重新确认开场”，重新执行完整复核。旧 POST 不做自动重试，不复用一次点击跨多次写入。 |
| `DEEPSEEK_NOT_CONFIGURED` | 刷新 Provider 摘要，保留阵容和排座，按配置区指引处理后重新确认。 |
| `ROSTER_SOURCE_CHANGED` / `ROSTER_SOURCE_NOT_FOUND` | 清除已接受历史绑定，失效并重读预览，带稳定原因返回同来源选择页；要求用户接受新来源或切普通模式。不得清除原因后自动接受。 |
| `ROSTER_MODEL_INACTIVE` | 显示“历史阵容当前无法开场，请从当前目录重新选择”并提供入口；不删减成员或映射为新版本。 |
| `INVALID_REQUEST` / 本地输入校验失败 | 明确阵容或座位无效，返回选择/调整；不展示原始响应体，不统一包装成网络重试。 |
| cancelled / 离页后的结果 | 由原 Query/runtime 完成安全收尾，旧页面不再显示新错误、修改草稿或导航。 |

错误处理前核对 runtime 是否已定位实际活动场次；提供继续入口，不因来源修复诱导重复开场。失败分支不能只读取一个可能是此前成功的 active null：必须确认原创建恢复读取已完成且当前 Query 为 success/idle，或主动完成一次失败之后的活动读取。

现有创建协议没有命令 ID 幂等；“当前未发现活动场次”也不是原 POST 一定回滚的证明。本设计承诺不自动重发，并在每次用户重新确认前读取状态；最终仍由服务端单活动约束处理原请求与再次提交的竞争，不新增持久化重试队列或假定 exactly-once。

### 7.5 离页、重入与迟到结果

本页操作标识在离开确认路由、来源切换、页面错误及草稿失效时作废；复核完成后发现作废则不发 POST。已经发出的创建 POST 不因离页被当作撤销，仍由 runtime 完成响应接收和缓存收尾。

迟到成功/失败只更新原 runtime/Query，不把用户从新页面拉回牌桌，不清空后来创建的新草稿。回到组桌时订阅 `isCreating()`，原请求尚在途则显示“正在确认开场结果”并关闭新提交；结束后通过原 active 查询定位。不能依靠已卸载页面的局部 pending 判断全局空闲。

横屏和隐藏可能发生在复核期间：不可交互时暂停新的提交；如复核结束时页面不可见，则终止本次提交并等待重新确认。已发 POST 照常收尾，恢复显示时按活动状态继续。无需新增离开确认弹窗或持久化草稿。
