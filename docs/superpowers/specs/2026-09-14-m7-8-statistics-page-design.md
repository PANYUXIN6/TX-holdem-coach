## 1. 设计结论与范围

将 `/statistics` 占位替换为真实统计页。默认展示“完成手统计 / 我的数据 / 全部时间”，以移动端卡片展示手牌数、所选完成手净盈亏和五项比率；可切换到“已结束场次账务”，查看最终筹码、全部买入与补码及整场净盈亏。两种视图分别读取现有 `GET /api/statistics` 的 `hands` 与 `sessions` 分支，一次只订阅当前分支。

顶部保留模式、主体和筛选摘要，筛选抽屉支持日期、场次、逻辑位置及历史 AI 人物配置；完成手模式另提供已有协议支持的按位置分组。URL 拥有已应用条件，TanStack Query 拥有服务端结果，React 局部状态仅保存抽屉草稿和展开意图。

完成标准：

1. 任务规定的所有筛选维度可组合、可重置，深链接、刷新及浏览器前进/后退恢复同一查询。
2. 明确区分参与者手数与实际牌局数、筛选后完成手收益与整场账务、用户与 AI 人物条件的不同含义。
3. 五项比率都显示中文定义、带名称的分子/分母及服务端百分比。零分母显示“—”，有分母而分子为零显示 `0%`。
4. 空样本、加载、失败和刷新失败可区分；切换条件、删除/清空及迟到响应不会把旧数据显示为新结果。
5. 360–430px 手机竖屏可阅读和操作，不依赖横向宽表；大字号与长金额保持可见。

现有接口没有时间序列，前端总体设计对趋势图规定的是展示形式，不是本任务新增序列接口的要求。因此本次只交付固定汇总和位置分组，不通过逐日多请求或拉取全部历史拼装趋势。设置、数据删除入口、Coach、EV、GTO、最优行动、打法评级、导出均不在本次实现范围。

本文拥有 A–D 研发切片的页面行为、共享边界和集成验收。切片不得改变 M5.4 的统计契约；若实施发现需要新接口或改变事实来源，先修订相关设计决定。

## 3. 信息结构与两种视图

页面从上到下为“统计”标题、模式切换、主体切换、已应用筛选摘要与筛选/刷新按钮、样本说明、结果卡片。按位置分组启用时，位置区跟在总计之后。

| 内容 | 完成手统计 `scope=hands` | 已结束场次账务 `scope=sessions` |
| --- | --- | --- |
| 样本 | 正常完成手，包括活动场次中此前已完成的手；不含进行中和中止手 | 已结束场次；不含活动及只读诊断场次 |
| 日期标签 | 手牌开手日期 / `handStartedAt` | 场次结束日期 / `sessionEndedAt` |
| 主数值 | 手牌数、所选完成手净盈亏、VPIP/PFR/3-bet/WTSD/W$SD | 已结束场次数、参与者场次数、最终筹码、全部买入与补码、已结束场次净盈亏 |
| 位置 | 筛选被统计参与者的开手逻辑位置；可按位置分组 | 无位置条件与分组 |
| 日期与盈亏关系 | 汇总符合开手时间等条件的完成手 | 汇总符合结束时间条件的整个场次，买入和手牌不按该区间再次裁剪 |

两种模式的结果标题直接使用以上净盈亏名称，不统一简写成“总收益”。金额单位为“筹码”，不添加货币符号或推导 BB/100。活动场次即使已有完成手，场次账务仍可为空；首手中止后结束的场次即使完成手数为零，仍可能有有效账务样本。

### 3.1 模式与主体切换

- 默认 `hands / user / groupBy=none`，其余条件为空，直接使用 `statisticsSearch.decode('')` 的规范化结果。
- “我的数据 / AI 数据”切换立即提交 URL，保留其他合法条件。人物条件摘要同步变为“对手包含此配置”或“仅统计匹配的 AI”，不暗中清除人物条件。
- 切到场次账务保留主体、日期、场次和人物条件，移除 position 字段、设 `groupBy=none`；切回完成手从 `position=null / groupBy=none` 开始，不从隐藏状态恢复旧位置。
- 模式区常显简短说明：“完成手按开手日期；账务按结束日期，位置条件仅用于完成手。”切换后立即更新实际日期口径；清除的位置/分组变化以非阻塞状态提示说明，无需确认弹窗。
- 每次模式/主体切换是一笔完整的合法 URL 更新，不能先发错误组合再补第二次更新；不预取另一种模式。相同条件不重复压入浏览器历史。
- 按位置分组属于完成手已应用查询条件，抽屉提供开关；不新增未列入原协议的展示参数。

## 4. 筛选、URL 与历史配置

### 4.1 已应用条件和抽屉草稿

有效 URL 经 `statisticsSearch.decode` 后才挂载结果查询。重复键、未知键、无效日期/标识、单独版本、`sessions+position`、`sessions+groupBy=position` 等按现有 codec 拒绝；显示“统计筛选参数无效”和返回默认统计的入口，不默默丢弃条件或发默认请求。编码与规范化继续经原 codec，保持 8192 字节预算。

抽屉使用原 `FilterDrawer`：打开时由当前 URL 建草稿；更改草稿不请求统计；应用成功才一次写入 URL，关闭后显示新条件对应的结果。重置只将草稿恢复到当前模式/主体下的不限条件（完成手同时取消分组），点应用才生效；取消不改 URL。页面上的非法参数重置入口则直接回默认 `/statistics`。

抽屉打开期间 URL 发生变化，包括后退或主体/模式改变，应关闭并丢弃旧草稿，不能把旧模式草稿提交到新页面。沿用 `searchKey` 与模态关闭/焦点恢复机制：抽屉关闭时由原模态机制恢复焦点，并保持内容滚动位置；pathname 不变的 search 更新保持当前焦点和滚动，不额外触发页面级滚动或聚焦。应用筛选及其后查询结果到达均不自动滚动或聚焦结果标题，普通后台刷新同样保持当前焦点和滚动位置。

验收时，让结果标题位于当前视口之外，在抽屉内用键盘应用一个会改变 Query Key 的合法筛选；确认只更新 search，关闭抽屉沿用原模态焦点恢复，内容未跳到结果标题，查询完成后也不发生额外滚动或焦点转移。

### 4.2 日期和场次

- 原生日期输入按浏览器本地时区解释，显式显示时区。开始日期转本地当天零点，结束日期“含当天”转本地下一天零点，再编码为 UTC `[from,to)`；次日使用日历运算，不固定加 24 小时。
- 未编辑日期时保留 URL 原始规范化 UTC 值和六位微秒；不得经过 `Date` 往返截断精度。非整日深链接展示精确的实际起止时刻与“不含上界”，说明日期控件编辑后才改为整日边界；未改动任一端不重算该端。
- 任一日期输入转换/校验失败都阻止应用，不保留旧有效值后伪装提交成功。只有一端时允许开放区间，两端都有时必须起点早于终点。
- 场次可用已知 UUID 精确指定，也可从历史选项逐批选择。选择场次不自动删除其他条件；筛选后为零仍是合法结果。
- 统计没有分页。历史选项的 cursor 只服务选项读取，不能进入统计 URL、统计 Key 或样本数量；不用逐页拉取手牌列表计算统计。

### 4.3 固化人物配置

“查找历史场次与人物”在主动展开后才读取 `queries.sessions`。沿用每批 20 项、显式下一批/回首批的有界方式，展示“本批场次 / 本批场次中的人物”，不把本批选项称为全量目录。选择器统一读取已有全部生命周期的场次列表，避免漏掉活动场次中的完成手；是否进入当前统计由统计接口判断。

人物选项从 `SessionManagement` roster 的固化字段读取，显示历史名称、人物 ID、版本和可展开的完整配置键。按配置键去重；相同名字但不同配置保留不同选项，不查当前人物目录推断历史身份。选择配置只设置 `configSnapshotKey`，同时清除 personaId/personaVersion/personaName；选择人物不自动绑定其来源场次。

保留“历史人物精确条件”展开区，支持已有 personaId、personaVersion、personaName、configSnapshotKey 组合与清除；高级条件全部作用于同一历史快照。纯空白、非规范正整数版本及无 ID 的版本按原规则报错；名称不自动 trim 或模糊匹配。直接 URL 的值不因当前选项批次找不到而消失；没有可认证名称时显示完整条件，不能猜名字。

| 主体 | 人物条件的页面解释 | 样本标签 |
| --- | --- | --- |
| 我的数据 | “只看对手阵容包含此历史配置的场次中的我的数据。”多个匹配 AI 不重复计用户 | 手牌数；实际牌局数可在样本说明中展示 |
| AI 数据 | “只统计自身符合此历史配置的 AI；未选配置时为全部 AI 汇总。” | AI 参与者手数及实际牌局数始终并列说明 |

位置在我的数据下标注“我的开手位置”，AI 下标注“AI 自身开手位置”；不是座位编号或我所面对的对手位置。清除人物条件一次清除四个字段，保留日期、场次等其他条件。

## 5. 指标展示契约

### 5.1 完成手总计

`handCount` 为获发底牌的参与者手数；`distinctHandCount` 为去重后的真实 Hand 数。例如一手六人桌全体 AI 可显示“AI 参与者手数 5，来自 1 手牌局”。不能把前者写成“完成了 5 手牌局”，也不能把后者拿来替换各比率分母。

`handNetChange` 直接展示为“所选完成手净盈亏”，解释为所选样本各参与者的结束筹码减开始筹码之和。只格式化符号、分组和单位，不读取场次摘要再算一次。

| 卡片标题 | 分子标签 | 分母标签 | 必须保留的解释 |
| --- | --- | --- | --- |
| VPIP · 翻前自愿入池率 | 自愿投入手数 | 参与者手数 | 强制盲注不计自愿投入 |
| PFR · 翻前加注率 | 翻前加注手数 | 参与者手数 | 每参与者每手最多计一次 |
| 3-bet · 翻前再加注率 | 完整再加注次数 | 合法 3-bet 机会次数 | 是机会次数，不是所有手数；不包含后续 4-bet 层级 |
| WTSD · 摊牌率 | 进入摊牌手数 | 看到翻牌手数 | 分母不是总手数或整桌曾发出翻牌的手数 |
| W$SD · 摊牌胜率 | 摊牌获得正派奖手数 | 进入摊牌手数 | 平分池也算获得份额；获派奖不等于该手净盈利 |

每张比率卡常显：标题、`percentage`、带名称的分子/分母、`StatisticsMetricDefinitions` 的对应中文定义；必要的解释用卡片内短句补充，不藏在 hover 提示里。卡片以“完整再加注 1 次 / 合法机会 3 次，33.33%”等有名称的数量表达，不只显示孤立的 `1/3`。

- `percentage=null` 显示“—”及“暂无分母样本”，同时保留 `0 / 0` 的带名称计数。
- 非 null 直接展示服务端已舍入结果，最多两位小数，可省略末尾零；`0%`、`100%` 均为有效结果。不除法重算、不平均位置或 AI 的百分比。
- 样本小仍显示原始计数与结果，不加任意样本门槛、排名、优劣颜色或风格标签。样本量由实际计数表达。
- 筹码及计数保留完整整数，不使用 k/万等缩略替代原值；收益正数带 `+`，负数保留负号，零显示 `0`。涨跌必须有符号与文字，不能只靠颜色。

### 5.2 按位置分组

`groupBy=none` 只展示总计；启用 `position` 后仍用同一响应，消费 `byPosition` 的 UTG、UTG+1、MP、LJ、HJ、CO、BTN、SB、BB 九项固定顺序。总计在顶部，九个位置各有独立纵向折叠区，标题常显位置、参与者手数和净盈亏，展开后使用与总计相同的指标卡及计数解释。

空位置也保留，标题注明“无样本”，展开显示零计数和“—”。同时指定 position 时仍保留协议返回的九项，不把其他空项冒充不存在的位置。位置展开只属于当前查询的局部状态；查询改变后恢复折叠，不写入 URL。

前端不加总各位置以生成总计；尤其 AI 的同一 Hand 可出现在多个位置组，`distinctHandCount` 不能跨组相加。每个组的实际牌局数只解释该组自身。

### 5.3 已结束场次账务

用同一响应展示 `sessionCount`（去重场次数）、`participantSessionCount`（参与者场次数）、`finalChips`、`cumulativeBuyIn` 和 `sessionNetChange`。AI 模式例如“1 个已结束场次，5 个 AI 参与者场次”，不将它写成“5 场”。

账务区常显说明：“整场净盈亏 = 最终筹码 − 全部买入与补码；日期按场次结束时间筛选。”例如服务端返回最终 2,700、全部买入与补码 3,000，显示净盈亏 −300。前端展示三项服务端数值，不用最后一手或筛选后的手牌收益推导账务。

此模式不显示 VPIP 等不存在的手牌字段，也不以零补齐。零场次时金额零配“暂无符合条件的已结束场次”；有场次但净盈亏为零表示有效的持平样本，不能当作空状态。

## 6. 查询、刷新与失败生命周期

| 状态/事件 | 页面行为与边界 |
| --- | --- |
| 首次读取，无成功数据 | 原 LoadingFeedback；不先渲染全零卡片。筛选仍可操作。 |
| 有效空响应 | 提示“暂无符合条件的完成手/已结束场次”，显示零计数和相应金额/比率空值，保留修改筛选入口；不称作请求失败。 |
| 无数据且请求失败 | 原 RequestError 安全文案与显式重试，不把服务异常变成无历史；输入错误引导改条件。 |
| 同一查询后台刷新 | 可保留上次成功卡片，标注“正在更新”；刷新失败显示“更新失败，以下为上次成功结果”和重试。已失效/重置且数据为空时不得从局部状态恢复旧卡片。 |
| 修改筛选、主体或模式 | 新 Key 只展示该 Key 的数据；不用上一 Key 的 placeholderData 过渡。旧请求由既有 signal/Query 生命周期取消或隔离，迟到结果不能进入当前视图。 |
| 手完成、场次结束、恢复 | 有既有 Session 租用时，由原 session-resources 定向失效：完成手影响 hands，结束影响 sessions，恢复校准影响相应范围。页面不自己推演增量。 |
| 删除整场或清空 | 原 mutation/runtime 冻结、取消、重置并重新查询；使用 Query 当前状态撤下旧统计，晚到响应不得恢复旧贡献。保留 URL 条件，已删除场次条件的新查询正常得到空汇总。 |

统计路由本身不持有 SessionRouteBridge 租用，也不因 sessionId 筛选去连接该场 SSE；不承诺跨标签页的即时同步。进入统计页、窗口重新聚焦、网络重连及点击“刷新”按原策略重新读取；用户可用刷新获取最新完成手/结算结果。不另加定时轮询或浏览器广播。

“刷新”只重读当前统计 Query，不清筛选、不重置历史选项游标、不请求另一个 scope；请求进行中禁用重复刷新。选项读取失败在抽屉局部处理，不抹掉主统计结果，也不将失败当成没有历史人物。

若删除期间抽屉已选某个旧配置，草稿可保留该筛选值，但不能保留已删除的 roster 数据副本；选项区随原查询重置，提交后该值按普通历史条件得到真实结果。

## 7. 移动端与可访问性

沿用 Shell 的 430px 最大画布、深色令牌、底部安全区与纵向滚动。总计手数和净盈亏可并列为两张短卡；含定义及分子/分母的五张比率卡优先纵向排列。空间或大字号不足时全部单列，不压缩正文以维持列数。位置分组用折叠卡，不用九列数据表。

模式和主体使用有分组标签的原生单选或等价可访问控件；选中态有文字/原生状态。日期、位置、场次与高级条件有明确 label；错误与字段关联，校验失败把焦点移至首个无效字段或错误摘要。FilterDrawer 继续拥有 focus trap、Escape、背景滚动锁、关闭后的焦点恢复。

数值区用等宽数字；完整 16 位安全整数、负号、长人物名和 64 位配置键均应自然换行或单列布局，不能截掉影响判断的数字。配置键可放到显式展开区，但精确条件必须可查看。收益符号、空值及失败都有文字解释；“—”给出可读的无分母说明。

浏览器验收覆盖 360×640、390×844、430×850、200% 文字、长名称与最大安全整数；测量页面、卡片、抽屉的横向溢出。沿用项目至少 44px 触控目标；更新只用小状态提示，不反复朗读全部指标或播放数值跳动动画。实际 iOS Safari/Android Chrome 日期输入、软键盘和手势安全区另列人工证据，桌面模拟不替代真机。
